# External LLaDA baselines

The adapters call the unmodified official implementations of
[ES-dLLM](https://github.com/zhuzj19/ES-dLLM) and
[SparseD](https://github.com/INV-WZQ/SparseD). Their source checkouts stay in ignored
runtime directories and are not bundled with Relay.

Both use the original pinned LLaDA-8B-Instruct checkpoint, BF16, batch size one,
the existing GSM8K 5-shot / MATH 4-shot / HumanEval 0-shot / MBPP 3-shot prompts,
seed 51713, and generation lengths 256 and 512. All use the existing
final-expression-v3 / Math-Verify 0.1.0 and official code execution scorers.
No LLaDA, Fast-dLLM or Relay result is regenerated by these entries.

| Method | Official profile used |
| --- | --- |
| ES-dLLM | Main Instruct HiddenState configuration, alpha 0.5, layer proportions 1/0.5/0.25 at relative depths 0/0.125/0.25; KV cache enabled; no extra parallel decoding |
| SparseD | README short-context configuration: skip 0.2, select 0.5, attention block size 32, generation block length 32 |

ES-dLLM retains its official task-specific generation blocks and refresh frequencies:
GSM8K 64/64/16, HumanEval and MBPP 64/64/4, MATH 256/256/8
(generation block / prompt refresh / block refresh). It retains its delayed EOS rule.
SparseD retains its fixed transfer schedule. On the RTX 5090, its FlexAttention
launch uses 64-by-64 compute tiles and two pipeline stages to fit shared memory;
the official attention mask, 32-token sparsity-selection tiles, scaling and
selection rule are unchanged. This execution adaptation is recorded in each manifest.
These are different decoding algorithms,
not lossless replacements for Relay or the original LLaDA trajectory.

Every prepared prompt receives a complete excluded warm request, then a timed replay.
The adapter checks that the two outputs and NFE agree. Request time includes the
official generator and its cache or sparse-pattern construction. Model loading,
prompt preparation, the warm request (including first-time compilation), decoding
text, scoring, persistence and progress rendering are outside request time.

Supply checkouts matching the revisions enforced by the adapters:

```bash
python -m dllm_eval.baseline_batch \
  --gpus 3 5 6 7 \
  --upstream-root /path/to/sources \
  --data-root /path/to/prepared-data \
  --hf-home /path/to/hf-home \
  --hf-hub-cache /path/to/hf-cache \
  --output runs/es-sparsed-full
```

The source directory must contain `es_dllm/` and `sparsed/` official Git checkouts.
Use `--dataset TASK=PATH` to override prepared dataset locations. The campaign first
checks two prompts per task at both lengths, then evaluates both complete tables.
Workers have exclusive GPU leases and per-run manifests. A frozen source copy
protects ongoing evaluation from later repository edits. All workers contribute to
one transcript in `log/`, with block progress bars and completed-cell tables.

The single-worker entry is `python -m dllm_eval.baseline_run`. It accepts
`--method es_dllm|sparsed`, `--baseline-source`, the usual evaluation arguments,
and explicit `--resume` for matching manifests. Existing records are preserved.
